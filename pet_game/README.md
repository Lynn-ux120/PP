# 高紫桐的小屋 · 2D 宠物养成

一个用 **Python + Pygame** 写的治愈系宠物养成小游戏。
主角「高紫桐」的形象完全由代码绘制（深色齐刘海 + 双马尾 + 白色蕾丝领衬衫 + 小花发饰），
参考工作区 `ppphoto.jpg` 的人物特征做了 Q 版卡通化处理，不需要任何外部图片素材。
她身边还养着一只**会自己行动的小宠物**。

**8 种互动 × 3 条数值 × 6 套可解锁衣装 × 4 只可解锁小宠物 × 20 种小动作。**
主角闲着没事会自己伸懒腰、蹦两下、歪头张望、蹲一会儿；
小宠物会打滚、追自己的尾巴、舔毛、刨地；每一套衣装和互动也都有自己的动作。

## 快速开始

```bash
pip install -r requirements.txt
python main.py
```

> 需要 Python 3.9+。程序会自动查找系统中文字体（微软雅黑 / 苹方 / Noto Sans CJK / 安卓系统字体…），
> 找不到时会退回 `SysFont`，一般不会出现方块字。

### 装到手机上玩

本目录已经可以直接打包成安卓 APK（配置在仓库根目录的 `buildozer.spec`，
云构建流水线在 `.github/workflows/build-apk.yml`）：

```bash
# GitHub 上推送代码后自动构建，Actions 页面下载 APK
# 或本地（Linux / macOS / WSL）：
buildozer android debug     # 产物：bin/*.apk
```

手机端适配全部收在 `platform_util.py` 一个文件里，**上面的游戏逻辑和绘制代码一行没改**：

- 640×800 逻辑画布等比缩放铺满任意手机屏幕，留白用背景渐变补齐（不是黑边）
- 触摸坐标自动换算回逻辑坐标；SDL 没给鼠标事件时用 `FINGER*` 兜底合成
- 安卓返回键：先收面板再退出；屏幕常亮 + 沉浸式全屏
- 桌面端尺寸不变时 `scale == 1`，直接就是原窗口，零额外开销

自测：`python tools/test_mobile.py`（33 项）

## 玩法

三条数值会随时间自动下降，用 **8 种互动** 去照顾她：

| 按钮 | 快捷键 | 效果 | 表现 |
| --- | --- | --- | --- |
| 喂食 | `F` / `空格` | 饱腹 **+26** | 小饼干飞向嘴边 + 咀嚼动画 |
| 喝水 | `D` | 饱腹 **+9** · 精力 **+8** | 小水滴飞向嘴边 |
| 抚摸 | `P` | 快乐 **+20** | 头顶冒出一串爱心 |
| 拥抱 | `H` | 快乐 **+15** · 精力 **+7** | 一大片爱心涌出 |
| 玩耍 | `Y` | 快乐 **+30** · 精力 **−17** | 星光炸开 + 额外弹跳 |
| 唱歌 | `G` | 快乐 **+22** · 精力 **−9** | 音符 ♪ 飘出 |
| 洗澡 | `B` | 快乐 **+12** · 精力 **+6** | 一串泡泡升起 |
| 睡觉 | `S` | 精力 **+69**（6 秒内回满） | 闭眼安睡 + 头顶 Zzz |

其他按键：`C` 衣橱 · `T` 宠物面板 · `1` / `2` / `3` 照顾小宠物 ·
`←` / `→` 换装（衣橱内）或换宠物（宠物面板内）· `R` 重新开始 · `ESC` / `Q` 退出。

### 数值与状态

- **饱腹值 / 快乐值 / 精力值**，默认每秒 −1.10 / −0.80 / −0.55。
- 精力低于 **16** 时「玩耍」会灰掉（太累了，先睡一觉）；
  其他互动则消耗精力，形成"陪玩 → 累了 → 睡觉"的小闭环。
- **睡觉**期间其余按钮全部灰显，睡觉按钮自身会变成 **☀ 叫醒**；
  睡眠中精力快速回复，饱腹/快乐的衰减降到 1/4。
- 数值低于 **52** → 变成"无聊"表情，并提示"她好像有点想你了"。
- 数值低于 **28** → **难过表情**：眼睛下垂、八字眉、撇嘴、眼角挂泪，数值条变红呼吸闪烁。
- 精力低于 **28** → **犯困表情**：眼皮耷拉、哈欠小圆嘴、眼角困纹；
  低于 **18** 会主动喊困。

## 衣装系统

右上角 **衣装** 按钮（快捷键 `C`）打开衣橱；也可以用 `←` / `→` 在
已解锁的衣服之间直接循环切换。

![衣橱](preview/20_wardrobe.png)

**6 套衣服**，其中 4 套要照顾到位才会解锁：

| 衣装 | 版型 | 解锁条件 |
| --- | --- | --- |
| 经典白裙 | 衬衫 | 默认拥有 |
| 樱花和服 | 连衣裙 | 默认拥有 |
| 星夜连衣裙 | 连衣裙 | 精力曾达到 **92** |
| 薄荷背带裙 | 背带裙 | 饱腹曾达到 **92** |
| 紫罗兰洋装 | 连衣裙 | 累计互动 **25** 次 |
| 熊熊连体服 | 毛衣 | 三条数值曾**同时**达到 **90** |

解锁条件是**基于历史峰值**判定的（`Pet._max_seen` / `interaction_count`），
所以"曾经喂饱过一次"就会永久解锁，不会因为数值掉下来又锁回去。
达成条件时会自动冒星光并喊你去看。

### 它是怎么画出来的

衣服**不是贴图叠加**，而是角色的绘制函数**读配置**直接画出来的 ——
`_draw_body` / `_draw_skirt` / `_draw_collar` / `_draw_arms` / `_draw_shoes` /
`_draw_headwear` 每个都接收一个 outfit 字典，按 `style` 和配色分支出不同造型。

四种版型：`blouse`（衬衫 + 蕾丝领）、`dress`（收腰 + 散摆裙 + 腰带）、
`sweater`（宽松 + 罗纹下摆 + 高领）、`overall`（白 T + 背带裙 + 小口袋）。
六种发饰：`flower` / `sakura` / `star` / `moon` / `ribbon` / `bear`。
图案：`none` / `star` / `flower` / `bear`。

所以**加一套新衣服只需要往 `config.OUTFITS` 里加一条字典**，不用写绘制代码：

```python
dict(id="snow", name="冬雪斗篷", hint="雪天专属",
     unlock={"stat": "happiness", "gte": 95},   # 快乐曾达 95 才解锁
     style="sweater",
     cloth=(238, 244, 255), shad=(214, 226, 246), inner=(255, 255, 255),
     trim=(186, 206, 236), bow=(150, 176, 226), tie=(150, 176, 226),
     shoe=(198, 214, 240),
     pin="star", pin_main=(214, 232, 255), pin_accent=(255, 250, 214),
     pattern="star", accent=(186, 210, 246)),
```

衣橱卡片、缩略图、锁定态、解锁条件文案、收集进度都会自动生成。
`unlock_text()` 负责把条件翻译成卡片上那句人话。

> 卡片里的缩略图是**用当前这只宠物实时渲染的**（`Pet.render_thumb()` 在内部分别
> 以六套衣服各渲染一次并缓存），所以卡片上看到的就是穿上后的真实样子，
> 改了衣服参数也不需要另外维护一套封面图。

## 小宠物系统

主角身边养着一只小动物 —— 你照顾她，她照顾它。
右上角 **宠物** 按钮（快捷键 `T`）打开宠物面板。

![宠物面板](preview/30_companion.png)

小宠物**有自己的数值、自己的 AI、自己的形象**，完全独立于主角：

| 宠物数值 | 说明 |
| --- | --- |
| **亲密** | 只增不减（感情不会随时间变淡），靠互动和摸它涨 |
| **饱腹** | 每秒 −0.85，投喂一口气 +28 |
| **心情** | 每秒 −0.55，逗它玩 +27 |

面板里三个按钮（快捷键 `1` / `2` / `3`）：

| 按钮 | 键 | 对宠物的影响 | 顺带对主角的影响 |
| --- | --- | --- | --- |
| 投喂 | `1` | 饱腹 +28 · 心情 +9 · 亲密 +4 | 快乐 +2 |
| 逗它 | `2` | 心情 +27 · 亲密 +10 · 饱腹 −4 | 快乐 +5 |
| 抱抱 | `3` | 亲密 +15 · 心情 +12 | 快乐 +6 |

**另外可以直接点草地上那只小动物**，等于摸摸它（亲密 +5 / 心情 +6）。

### 它会自己行动

小宠物不是一个跟着主角位移的装饰图，它有一套状态机：

`idle`（发呆）→ `walk`（溜达）→ `sit`（坐下）→ `sleep`（打盹）→
`chase`（追蝴蝶）→ `nuzzle`（饿了跑去蹭主角讨食）

大部分时候它会待在主角的**左右两侧**（不会站到她身上去），偶尔跑远逛一圈，
追蝴蝶时会一颠一颠地小跑，追到了还会冒星光。心情好时尾巴摆得快。

**它和主角之间有真实的联动**：

- 宠物三项数值都好 → 主角的**快乐值衰减 ×0.85**（她省心）
- 宠物饿了 / 委屈 → 主角的**快乐值衰减 ×1.15**（她跟着操心），
  宠物自己会跑去她身边冒爱心讨食
- 你让主角**睡觉**，小宠物会自动跑到她旁边**一起睡**（并飘 Zzz）
- 你陪小宠物玩，主角也会跟着开心（见上表最后一列）

### 四只小宠物要慢慢认识

| 小宠物 | 造型 | 解锁条件 |
| --- | --- | --- |
| 咪咪 | 三花猫 | 默认拥有 |
| 豆豆 | 垂耳兔 | 亲密度曾达到 **60** |
| 团子 | 柴犬 | 宠物互动累计 **25** 次 |
| 啾啾 | 小肥鸟 | 宠物三项数值曾**同时**达到 **88** |

和衣装一样，解锁用**历史峰值**判定，达成即永久解锁，并会自动冒星光喊你去看。

| | | |
| --- | --- | --- |
| ![三花猫](preview/32_1_pet_cat.png) | ![垂耳兔](preview/32_2_pet_rabbit.png) | ![小肥鸟](preview/32_4_pet_bird.png) |

### 它也是"画"出来的

四只小宠物共用一套绘制流程（`_draw_body` / `_draw_ears` / `_draw_tail` /
`_draw_face` / `_draw_markings`），靠 `kind` 分支出不同造型：

- **耳朵**：三角尖耳（猫 / 柴犬）/ 长椭圆耳（兔）/ 头顶呆毛（鸟）
- **尾巴**：长弯尾（猫）/ 圆球尾（兔）/ 卷尾（柴犬）/ 扇形尾羽（鸟）
- **花纹**：头顶橘斑（三花的标志）/ 白色口鼻（柴犬）/ 白肚皮 + 翅膀（鸟）
- **难过时耳朵会垂下来**，四种表情（普通 / 开心 / 委屈 / 睡着了）都是状态机驱动

所以**加一只新宠物只需要往 `config.COMPANIONS` 里加一条字典**，
造型复用现有的 `cat` / `rabbit` / `shiba` / `bird` 即可。
宠物面板的卡片、缩略图、锁定态、解锁条件文案、收集进度全部自动生成。

## 动作系统

角色和小宠物都由一条"待机呼吸"升级成**会自己找事做**：闲着的时候按权重抽一个小动作播，
每个互动、每套衣装也都有自己的动作。

### 主角的小动作

待机 3.5~7 秒后开始，之后每隔 6~15 秒随机挑一个（表在 `config.PET_ANTICS`）：

| 动作 | 表现 | 附带 |
| --- | --- | --- |
| 伸懒腰 | 整体拔高、收窄，慢慢回弹 | 星光 |
| 哼歌摇摆 | 左右晃 + 身子跟着歪 | 音符 ♪ |
| 原地蹦跳 | 跳两下，落地压扁、腾空拉长 | 星光 |
| 歪头张望 | 歪 15° 停一会儿再回正（左右随机） | 台词 |
| 蹲一会儿 | 整个矮一截 | 台词 |
| 转个圈 | 原地旋转一整圈 + 轻轻离地 | 星光 |
| 打哆嗦 | 高频小幅抖动 | —— |

**心情会改变动作池**（`config.PET_MOOD_ANTICS`）：难过时只会缩着发抖、
犯困时只会打瞌睡、无聊时动作也收敛一些 —— 不会出现"她都快哭了还在原地转圈"。

### 每个互动都有自己的动作

不用写新方法，只要在 `config.INTERACTIONS` 的那一行上加 `motion=("曲线名", 秒数)`：

| 互动 | 动作 | 互动 | 动作 |
| --- | --- | --- | --- |
| 喂食 | 低头点头 | 玩耍 | 蹦跳 |
| 喝水 | 仰头 | 唱歌 | 摇摆 |
| 抚摸 | 舒服地晃 | 洗澡 | 甩水 |
| 拥抱 | 被挤压回弹 | 照顾宠物 | 低头吃 / 扑过去 / 挤一挤 |

而且你**去陪小宠物玩的时候，她会好奇地歪头看过去**（`_glance_at_companion()`）。

### 小宠物的自娱自乐

小宠物的 AI 换成了一张**权重表**（`config.COMP_AI_TABLE`），想改它的性格改那里就行：

| 行为 | 权重 | 行为 | 权重 |
| --- | --- | --- | --- |
| 待在主角附近溜达 | 32 | 打滚（侧着滚两下） | 6 |
| 跑去远处逛 | 11 | 追自己的尾巴（原地打转） | 6 |
| 坐下歇会儿 | 11 | 刨地 | 5 |
| 舔毛 | 8 | 追蝴蝶 | 10 |
| 伸懒腰 | 7 | 打个盹 | 2 |

做打滚 / 追尾巴 / 伸懒腰时会顺手冒星光，偶尔还会"喵"一声。

### 它是怎么实现的

动作**不是逐帧手画的**，而是一组**数学曲线**：一条曲线接收归一化进度 `p ∈ [0,1]`，
返回一组变换量（位移 / 缩放 / 旋转）。同一条曲线主角和小宠物共用 ——
曲线只管节奏，画多大由各自的调用处决定。

```
motion.py
├─ Pose              一帧的变换量，支持相加合成
├─ c_stretch / c_hop / c_sway / c_tilt / c_squat / c_twirl / c_shiver
├─ c_shake / c_sip / c_squeeze      ← 互动用
├─ c_roll / c_spin / c_groom / c_dig / c_nod   ← 小宠物用
├─ MotionPlayer      play(名字, 时长, 方向) → update(dt) → pose()
└─ weighted_choice   按权重抽一个动作
```

所有曲线都满足两条约定：**p=0 和 p=1 时归零**（不会"啪"地跳回原位），
以及**幅度有界**（不会把角色拉变形）—— 自测里对这两条逐一做了断言。

> 曲线函数里不写"像素"，只写比例，所以同一份"伸懒腰"直接用在 300px 高的主角和
> 132px 高的小宠物身上都成立。想同时调整两边的"手感"，改 `motion.py` 一处即可。

### 六个关键设计

**① 超采样画笔（`utils.Pen`）**
所有角色绘制都用"逻辑坐标"，内部放大 `CHAR_SUPERSAMPLE` 倍渲染，最后
`smoothscale` 缩回 1x。这样即便是 pygame 最原始的 `draw.circle` 也能得到
平滑的手绘感边缘，同时代码里写的还是直观的坐标。主角和小宠物共用它。

**② 贴图缓存**
角色形状只和「衣装 / 表情 / 是否眨眼 / 咀嚼帧 / 泪滴帧」这几个离散状态有关，
小宠物也只和「品种 / 表情 / 尾巴帧 / 朝向」有关，所以 `_render()` 按这个元组
做缓存。呼吸、跳跃、挤压拉伸这些连续动画放在 `draw()` 里通过整体位移和缩放实现。

**③ 逻辑与表现解耦**
`Pet.update()` / `Companion.update()` 只管数值和计时器，不直接创建特效；
`main.py` 在拿到互动结果后调用 `particles.spawn_*()`。
要换一套特效表现，不用动宠物代码。

**④ 互动表驱动**
所有互动都写在 `config.INTERACTIONS` / `config.COMPANION_ACTIONS` 里
（数值增减 / 冷却 / 前置条件 / 特效 / 台词 / 按钮配色），
`interact(id)` 和按钮网格、快捷键映射都从这里自动生成 —— **加互动基本不用写逻辑代码**。

**⑤ 衣装参数化**
衣服不是素材图，而是绘制函数读 `config.OUTFITS` 里的字典现场画出来的。
版型（4 种）× 配色 × 发饰（6 种）× 图案（4 种）自由组合，
**加一套衣服 = 加一条字典**，其它全部自动生成。

**⑥ 宠物 AI 状态机**
小宠物不是"跟着主角飘"的装饰，而是一个独立的实体：自己挑目标点、
自己决定走 / 坐 / 睡 / 追蝴蝶 / 打滚，饿了会主动跑去主角身边讨食，
主角睡了它也睡。判定和绘制完全在 `companion.py` 里，和主角代码没有耦合，
`Companion.update(dt, host, particles)` 只通过 `host.x` / `host.sleeping`
两个字段"看见"主角。

**⑦ 动作曲线与渲染分离**
所有小动作都是"曲线算出一组变换量 → 叠加到整体位移/缩放/旋转上"，
**不动贴图、不重画**。这带来两个好处：贴图缓存完全不受动作影响
（动作再花也不会掉帧），以及同一条曲线能同时用在身量差一倍的主角和小宠物身上。
姿态的落地统一交给 `utils.posed_blit()` —— 它以"脚底"为锚点做缩放，
旋转时则以静止中心为轴，所以转圈不会绕着脚底画大圈。

### 5. 加一个小动作（例如「拍手」）★ 两步，通常不用写画法

`motion.py` 里已经有 14 条现成曲线（伸懒腰 / 蹦 / 摇 / 歪头 / 蹲 / 转圈 /
哆嗦 / 甩 / 仰头 / 挤压 / 打滚 / 追尾巴 / 舔毛 / 刨地 / 点头），
先看能不能拼出来；不行再写新曲线：

```python
# ① motion.py —— 写一条曲线（只需要保证 p=0 / p=1 时归零）
def c_clap(p: float) -> Pose:
    e = envelop(p, 0.2, 0.25)
    a = p * TAU * 5.0
    return Pose(dy=-abs(math.sin(a)) * 4.0 * e,     # 一颠一颠
                sx=1.0 + 0.05 * math.sin(a) * e)    # 一收一放
MOTION_LIB["clap"] = c_clap

# ② config.py —— 让主角在待机时偶遇它
dict(id="clap", motion="clap", dur=(1.4, 1.8), weight=12.0,
     effect="music", speech="antic_clap", next=(7.0, 12.0)),
# 顺手在 SPEECH 里补个台词池
"antic_clap": ["啪啪啪～", "给你鼓掌！"],
```

**就这两步**。如果只想让某个互动做这个动作，跳过 ②，直接在那条互动上加
`motion=("clap", 1.5)` 即可。

加完记得跑一下自测思路里的两条约定（首尾归零、幅度有界）——
`tools/screenshot.py` 会把 `40_antic_*.png` 渲染出来，一眼就能看出有没有问题。

## 已知说明

- 「饱腹值」按需求描述"随时间下降、喂食恢复"，语义上等同于**饥饿值**。
  若你想改成"越饿数字越大"，把 `HUNGER_DECAY` 改成负值并调整显示文案即可。
- 背景为一次性预渲染的 `Surface`，飘云、角色、小宠物、粒子是每帧动态绘制。
- 半透明粒子和小部件都在"刚好包住自己"的小图层上作画 —— 早期版本每帧分配
  十几个整屏 `Surface`，性能会掉到 15ms/帧；改成小图层后降到 0.9ms。
- 小宠物**画在主角之前（前景）**：它的贴图比主角窄很多，如果按 x 排序做遮挡，
  它走到主角站的区域时会被整张盖掉（真的踩过这个坑）。现在改为始终画在
  主角前面，并让 AI 把活动目标点限制在主角左右两侧。
- 动作曲线有两条硬约定，加新曲线时请一并遵守：**首尾归零**（否则动作结束会
  "啪"地弹一下 —— `c_hop` 一开始就犯过这个错：`|cos|` 在 p=1 处不等于 1）
  与**幅度有界**（否则转圈/拉伸会把角色拉变形）。
- 小宠物的"打滚"最早写的是**旋转整整一圈**，结果转到 180° 时它变成头朝下，
  看起来像倒挂着的猫，很怪。二维平面里"侧滚"只能靠小角度倾斜 + 左右位移来演，
  所以现在滚的是 ±27°。同理"追尾巴"的横向压缩到 0 会压成一条线，留了 0.38 的底。
- 动作只做**整体变换**（位移 / 缩放 / 旋转），不重画贴图 ——
  所以贴图缓存不受动作影响，加再多动作也不会掉帧。
